14Handling and downtimes as view kinds (round 5)round 5

Round 5 makes the model coherent with topic 04: handling and downtimes are view kinds, next to list, grouped list, host-group grid, summary tiles and event stream. A dashboard is a stack of views, each with its own filter; a full-page handling dashboard is simply a dashboard with one handling view. 04’s rule applies unchanged: only problem views count toward the sidebar number and notifications, so handling, downtimes and event views never notify. New dashboard opens the editor at once with one empty list view (a); the editor is 04’s (b); views combine freely (c); the sidebar shows what a dashboard holds (d). View controls (every view kind): a view has one set of controls, always in its view header; on a one-view dashboard that header is the page header and the controls are roomy (b, d), stacked they are compact (c). Row density per view: the settings’ row density is the default; a list-like view can set its own (the header’s toggle, the view’s ···, the editor). Sidebar mark: each dashboard chooses state or an icon, with an icon picker (e, f, g). The cluster section becomes handling, downtimes, events and health; the first three are the same views without a filter. Every view’s filter field has copy filter from (round 4, 14-r4-e).
