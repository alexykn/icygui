11Read-only Icinga config: the command line, and who Icinga notifies

Lower priority; this topic is meant to help decide. It adds two read-only things to the host pane's config tab and the service pane's check section. First, the check command's actual command line, with every argument resolved from the object's macros, and where each value comes from. Second, who Icinga would notify: each notification object with its users and user groups, their email and pager, the time period, and the states and types. Both need API permissions icygui doesn't ask for today: objects/query/CheckCommand for the first, objects/query/User, UserGroup and TimePeriod for the second. Without them the sections say what is missing and show what is known from today's objects (frame 11c). Protected values (passwords, tokens, community strings) are always ***.
